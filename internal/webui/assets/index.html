What is queuesim?

Two real distributed-systems designs — Temporal's matching + history machinery and a Tasqueue worker pool — rebuilt as deterministic queue-network models. No containers, no cluster, no wall clock: a seeded event loop advances simulated milliseconds and every mechanism (sync-match, spooling, retries, persistence, fan-out) is a queue you can watch.

Why determinism matters

The same configuration and seed produce a byte-identical trace. That makes results debuggable: a surprising number is a reproducible experiment, not a flake. Press Verify replay to rerun the exact request and compare digests, or Sweep seeds to see which conclusions hold across random draws.

Reading the page

  • The mechanism map animates the live state: bars are queue depths, numbers are instantaneous gauges. The timeline below it is the same run, scrubbable.
  • Attempts per start is the retry-amplification headline: 1.0 means a workflow's activity succeeded first try; 3.0 means it took three attempts on average.
  • Schedule-to-start latency measures from a task entering matching to a poller taking it.
  • Turn knobs, then press Run. Nothing is hidden: the trace JSON is downloadable.
  • Space plays or pauses, ← / → step the timeline, ⌘/Ctrl+Enter runs. Copy permalink encodes the scenario, seed, knobs, and the moment you are looking at.

Honesty note

These are models, not the real systems. Constants are pinned to the real server where the source defines one, calibrated where it does not, and labeled as such in the model packages. The point is mechanism intuition, not a benchmark.
